# 주택파동 최종 발표 요약

10분 발표, 9~10장 기준입니다. 기술 구현보다 “분산 데이터가 왜 사업 단위로 연결되지 않는가”라는 발견을 중심에 둡니다.

## 1. 왜 주택파동인가 (0:00–0:50)

- 핵심 문장: 공급량만으로는 사업의 실제 진행상황과 데이터 공백을 알 수 없다.
- 내용: 정책부터 입주까지 단계별 데이터가 흩어진 문제.
- 시각자료: 6단계 흐름 단일 다이어그램.
- 발표자: “공식 데이터는 많지만 한 사업의 흐름으로 보기 어렵습니다.”

## 2. 문제와 사용자 (0:50–1:40)

- 핵심 문장: 정책 담당자와 국민 모두 사업 단위의 공급 흐름을 필요로 한다.
- 내용: 정책 담당자·국민, 공통 Project ID 부족, 계획/실적 혼동.
- 시각자료: 분산된 source → 단절된 사업 추적.
- 발표자: “각 데이터는 공식이지만, 서로 같은 사업임을 증명하기 어렵습니다.”

## 3. 주택파동의 접근 (1:40–2:30)

- 핵심 문장: 데이터를 합쳐 보이기 전에 원문·검증상태·연결 근거를 보존한다.
- 내용: RAW → Candidate → Project Master → Analytics → Dashboard.
- 시각자료: 시스템 architecture.
- 발표자: “불확실한 데이터는 억지로 연결하지 않고 검토 대상으로 남깁니다.”

## 4. 6단계 공급 lifecycle (2:30–3:15)

- 핵심 문장: 정책, 사업화, 인허가, 건설, 공급, 입주는 서로 다른 데이터 의미다.
- 내용: 공급계획≠공급완료, 입주예정≠실제입주, 건설호수≠공급호수.
- 시각자료: Dashboard pipeline.
- 발표자: “숫자를 합치기보다 각 숫자의 의미를 먼저 분리했습니다.”

## 5. 실제 데이터 구축 결과 (3:15–4:15)

- 핵심 문장: LH 수도권 공급계획으로 LIVE Project Master 23건과 8,072호를 구축했다.
- 내용: 서울 3·경기 15·인천 5, 원문 48행, MIXED 모드.
- 시각자료: LIVE 사업 목록과 지역 필터.
- 발표자: “실제 사업은 지도 좌표가 없어 marker를 만들지 않았습니다.”

## 6. 상황판 시연 (4:15–5:30)

- 핵심 문장: 상황판은 공급 흐름뿐 아니라 데이터 상태를 함께 보여준다.
- 내용: 필터, Pipeline, LIVE/DEMO badge, upcoming, coverage.
- 시각자료: 1920×1080 Dashboard 캡처.
- 발표자: “MIXED는 오류가 아니라 실제와 시연 데이터를 투명하게 구분한 상태입니다.”

## 7. 실제 연결 실험 (5:30–6:50)

- 핵심 문장: 23개 실제 사업에서 80개 검색어로 공식 공고를 역검색했다.
- 내용: 55 PAN_ID, 상세 55건, 지구 55·블록 26·주소 55, 공급호수 0.
- 시각자료: [역검색 보고서](lh_project_search_report.md) 수치 표.
- 발표자: “같은 LH 데이터라도 공통 식별자가 부족해 자동 확정은 위험했습니다.”

## 8. Human-in-the-loop 검토 (6:50–7:50)

- 핵심 문장: 연결률보다 오매칭 방지가 우선이다.
- 내용: evidence 비교, REVIEW_REQUIRED, VERIFIED/REJECTED audit, block-only 금지.
- 시각자료: 연결 검토 화면.
- 발표자: “검색 결과는 후보 생성 근거일 뿐 자동 MATCHED가 아닙니다.”

## 9. 한계와 정책적 시사점 (7:50–9:10)

- 핵심 문장: 문제는 공식 데이터 부재보다 공식 데이터 간 연결키 부재다.
- 내용: 공통 Project ID, provenance, 계획/실적 분리, 품질 상태 공개.
- 시각자료: source별 ID/주소/좌표 공백 표.
- 발표자: “strong match 0은 실패가 아니라, 안전한 연결 기준을 실제로 검증한 결과입니다.”

## 10. 결론 (9:10–10:00)

- 핵심 문장: 주택파동은 진행상황과 데이터 공백을 함께 보여주는 통합 상황판 PoC다.
- 내용: 6단계 lifecycle, 23 LIVE projects, 품질 관리 workflow, 확장 조건.
- 시각자료: 핵심 성과 5개.
- 발표자: “다음 구축의 출발점은 더 많은 크롤링이 아니라 기관 간 공통 Project ID입니다.”
